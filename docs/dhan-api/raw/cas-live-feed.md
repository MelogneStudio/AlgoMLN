# CAS Live Feed

Closing Auction Session data via WebSocket — indicative equilibrium price, depth and indicative index values

(Pro Traders Plan)

CAS Live Feed streams Closing Auction Session (CAS) data real-time via WebSocket. Each instrument packet carries the **Indicative Equilibrium Price (IEP)**, the total buy and sell quantity at that IEP, market depth, the indicative imbalance quantity and the reference price for the session.

Along with the instrument level packet, an indicative index packet is streamed which carries the indicative close value of the index.

Similar to [Live Market Feed](/api/v2/live-market-feed), all request messages over WebSocket are in JSON whereas all response messages over WebSocket are in Binary.

## Establishing Connection

To establish connection with DhanHQ WebSocket for CAS Live Feed, you can connect to the below endpoint using WebSocket library.

```
wss://api-feed.dhan.co?token=<your-access-token>&clientId=<your-client-id>&authType=2
```

**Query Parameters**

| Field | Description |
|-------|-------------|
| token* | Access Token generated via Dhan |
| clientId* | User specific identification generated by Dhan |
| authType* | 2 by Default |

## Adding Instruments

For subscribing, this can be done using JSON message which needs to be sent over WebSocket connection.

**Request Structure**

```json
{
    "RequestCode" : 23,
    "InstrumentCount" : 1,
    "InstrumentList" : [
        {
            "ExchangeSegment" : "NSE_EQ",
            "SecurityId" : "1333"
        }
    ]
}
```

## Keeping Connection Alive

To keep the WebSocket connection alive and prevent it from closing, the server side uses **Ping-Pong** module. Server side sends ping every 10 seconds to the client server (in this case, your system) to maintain WebSocket status as open.

An automated pong is sent by websocket library. You can use the same as response to the ping.

In case the client server does not respond for more than 40 seconds, the connection is closed from server side and you will have to reestablish connection.

## Response Structure

The CAS data is sent as structured binary packet. It will require parsing to readable format to extract the relevant information.

All responses from Dhan Market Feed consists of [Response Header](#response-header) and Payload. Header for every response message remains the same with different [feed response code](/api/v2/annexure#feed-response-code), while the payload can be different.

### Response Header

The response header message is of 8 bytes which will remain same as part of the response messages. The message structure is given as below.

| Bytes | Type | Size | Description |
|-------|------|------|-------------|
| 0 | [ ] byte | 1 | Feed Response Code can be referred in [Annexure](/api/v2/annexure#feed-response-code) |
| 1-2 | int16 | 2 | Message Length of the entire payload packet |
| 3 | [ ] byte | 1 | Exchange Segment can be referred in [Annexure](/api/v2/annexure#exchange-segment) |
| 4-7 | int32 | 4 | Security ID - can be found [here](/api/v2/instruments) |

### CAS Packet

This data packet consists of the indicative equilibrium price of the subscribed instrument, along with the quantities at that price, market depth, imbalance quantity and the reference price, in a single packet of 128 bytes.

| Bytes | Type | Size | Description |
|-------|------|------|-------------|
| 0-7 | [ ] array | 8 | [Response Header](#response-header) see [annexure](/api/v2/annexure#feed-response-code) |
| 8-11 | float32 | 4 | Indicative Equilibrium Price (IEP) |
| 12-15 | int32 | 4 | Total buy quantity at IEP |
| 16-19 | int32 | 4 | Total sell quantity at IEP |
| 20-119 | Market Depth Structure | 100 | 5 packets of 20 bytes each for each instrument in below provided structure |
| 120-123 | int32 | 4 | Indicative imbalance quantity at IEP |
| 124-127 | float32 | 4 | Reference price for CAS (from transcode `7338`) |

Each of these 5 packets will be received in the following packet structure:

| Bytes | Type | Size | Description |
|-------|------|------|-------------|
| 0-3 | int32 | 4 | Bid Quantity |
| 4-7 | int32 | 4 | Ask Quantity |
| 8-9 | int16 | 2 | No. of Bid Orders |
| 10-11 | int16 | 2 | No. of Ask Orders |
| 12-15 | float32 | 4 | Bid Price |
| 16-19 | float32 | 4 | Ask Price |

### CAS Indicative Index Packet

Along with the instrument level CAS packet, an indicative index packet of 33 bytes is streamed which carries the indicative close value of the index. Note that the field order of this packet differs from the [Response Header](#response-header) — the message length is sent first, followed by the message code.

| Bytes | Type | Size | Description |
|-------|------|------|-------------|
| 0-1 | int16 | 2 | Message Length of the entire payload packet |
| 2 | uint8 | 1 | Feed Response Code can be referred in [Annexure](/api/v2/annexure#feed-response-code) |
| 3 | uint8 | 1 | Exchange Segment can be referred in [Annexure](/api/v2/annexure#exchange-segment) |
| 4-24 | [21] byte | 21 | Index Name |
| 25-32 | float64 | 8 | Indicative Close Value of the index |

## Feed Disconnect

Removing instruments from the feed and closing the feed entirely are two
different operations, with two different request codes.

### Delete subscription — `24`

Request code `24` stops the CAS feed for the instruments you name in the
message. Like subscribing, it must carry the full request structure, including
`InstrumentCount` and `InstrumentList`:

```json
{
    "RequestCode" : 24,
    "InstrumentCount" : 1,
    "InstrumentList" : [
        {
            "ExchangeSegment" : "NSE_EQ",
            "SecurityId" : "1333"
        }
    ]
}
```

### Disconnect the feed — `12`

To close the entire CAS feed, send request code `12` on its own. No instrument
list is needed, and it closes the feed irrespective of the request code
currently in use:

```json
{
    "RequestCode" : 12
}
```

### Server-side disconnection

In case of WebSocket disconnection from server side, you will receive disconnection packet, which will have disconnection reason code.

- If more than 5 websockets are established, then the first socket will be disconnected with `805` with every additional connection.

| Bytes | Type | Size | Description |
|-------|------|------|-------------|
| 0-7 | [ ] array | 8 | [Response Header](#response-header) with code `50` see [annexure](/api/v2/annexure#feed-response-code) |
| 8-9 | int16 | 2 | Disconnection message code - [here](/api/v2/annexure#data-api-error) |

You can find detailed Disconnection message code description [here](/api/v2/annexure#data-api-error).


### Response Fields

| Field | Type | Required | Description |
|-------|------|----------|-------------|
| RequestCode | int | Yes | Code for subscribing to CAS Live Feed see [annexure](/api/v2/annexure#feed-request-code) Values: `23`. |
| InstrumentCount | int | Yes | No. of instruments to subscribe from this request |
| InstrumentList.ExchangeSegment | enum string | Yes | Exchange Segment of instrument to be subscribed see [annexure](/api/v2/annexure#exchange-segment) |
| InstrumentList.SecurityId | string | Yes | Exchange standard ID for each scrip. refer here |
